# オセロ：ルールと AI の設計

## ルール
- 盤面 8×8、黒が先手。初期配置は d4・e5 が白、d5・e4 が黒。
- マス番号 `sq = y * 8 + x`（x: 列 a〜h = 0〜7、y: 行 1〜8 = 0〜7）。棋譜は `f5d6c3…`（パスは書かない）。
- 打てる場所がなければパス。両者とも打てなければ終局。
- 終局の石差は「空きマスは勝った側のもの」として数える。

実装は 2 つあり、同じ結果になることをテストで確かめている（`shared/fixtures/othello/engine_cases.json`）。

| | 場所 | 用途 |
|---|---|---|
| Python | `backend/games/othello/board.py`（ビットボード） | 自己対戦の学習、棋譜の検証 |
| TypeScript | `frontend/src/games/othello/engine/board.ts`（配列） | 画面、AI の探索 |

ルールを変えたら両方を直し、`cd backend; python -m games.othello.fixtures` でテストデータを作り直して
`pytest` と `npm test` を通す。

## AI の設計（なぜ強いか）

```
[学習: Python]  自己対戦 + TD 学習で「形ごとの点数表」(n-tuple) を育てる
                    ↓ runs/othello/<学習名>/checkpoints/best.npz
[配信: Django]  GET /api/othello/agents/<id>/weights/ （Float32 の並び）
                    ↓
[対局: ブラウザ] Web Worker で アルファベータ探索 + その点数表で評価 + 終盤は完全読み
```

1. **評価関数 = n-tuple ネットワーク**（`backend/rl/othello/ntuple.py`）
   - 辺・角・斜めなどの「マスの並び」ごとに、石の置き方（3^n 通り）それぞれの点数を持つ。
   - 盤面の評価値 = 盤上の全パターンの点数の合計（回転・反転した同じ形は点数を共有）。
   - 序盤・中盤・終盤で形の価値が違うので、石の数で 6 段階に分けて別の表を持つ。
   - 強豪ソフト（Logistello・Edax）と同じ考え方。
2. **学習 = 自己対戦の TD 学習**（`backend/rl/othello/train.py`）
   - 評価値は「手番側から見た最終石差 / 64」の予想。
   - 1 手ごとに「一番よい手を打った後の価値」を目標にして、今の局面の予想を近づける。
   - 終局した手は本当の石差が目標になる。その情報が終局 → 中盤 → 序盤へ伝わっていく。
3. **探索 = アルファベータ法**（`frontend/src/games/othello/engine/search.ts`）
   - 評価関数だけでは相手の応手を考えられないので、何手も先まで読む。
   - 深さ 1, 2, 3 … と順に深くし、時間切れで止める（反復深化）。
   - 空きマスが少なくなったら終局まで全部読んで、正確な石差で打つ（完全読み）。
   - ブラウザの Web Worker で動くので、サーバーの負荷はかからない（公開時も無料で動かしやすい）。

### 強さの測り方
- 学習中: 学習した評価関数で **1 手だけ読んで** 打ち、ランダム・マスの重み表（1 手読み・2 手読み）と
  先後を入れ替えて対戦させた勝率（`backend/rl/othello/evaluate.py`）。
- 対局画面では何手も先まで読むので、表示されている勝率よりさらに強い。
- 人との対局は終局時に保存され、`/othello/stats` の「人との対局成績」に出る。
