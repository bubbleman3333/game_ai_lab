# rl/poker/ ポーカー AI の学習

ヘッズアップ（1 対 1）ノーリミット・テキサスホールデム。ルールは [games/poker/](../../games/poker/)、
API は [apps/poker/](../../apps/poker/README.md)。

**本命は「ニューラルネット（Deep CFR）+ その場で解くソルバー」**（`search.py` / `solver.py`）。
GTO Wizard などのソルバーと同じ考え方で、目の前の局面をナッシュ均衡に向けてその場で解く。
ネットは学習で得た平均戦略を「相手のレンジを推定するモデル」として使う。
ネットだけで打つ版（比較用）と、最初に作った表形式（tabular MCCFR）も残してある（`train.py` / `mccfr.py`）。

## なぜテトリスやオセロと作りが違うのか

このリポジトリのほかのゲームは**盤面が全部見える**ので、「この局面の価値」を学べばよかった。
ポーカーは**相手の手札が見えない**ので、同じやり方が通じない。

- 決まった打ち方は必ず読まれる。**手を確率で混ぜる**必要がある。
- 価値を学ぶ自己対戦（DQN・TD）は**収束しない**。じゃんけんと同じで
  「グー偏重 → パー偏重 → チョキ偏重」と巡回するだけになる。

そこで **CFR（Counterfactual Regret Minimization）**を使う。
「あの場面でこの手を選んでいれば、どれだけ得だったか」という**後悔**をためていき、
後悔の大きい手を選ぶ確率を上げる。平均戦略はナッシュ均衡に近づく。

ヘッズアップのゼロサムでは、均衡に近い戦略は**どんな相手に対しても期待値で負けない**。
これが「簡単に退場しない強さ」の正体で、運が悪い日はあっても、長い目で見てカモにされない。

## 3 つの作り

| | その場で解く（本命） | ニューラルネットだけ | 表形式版（先に作った方） |
|---|---|---|---|
| 打ち方の決め方 | **対局中に局面を解く**（CFR+・レンジ付き） | 学習した平均戦略をそのまま | 学習した表をそのまま |
| 後悔のしまい場所 | 木の各ノード（局面ごとに作り直す） | ニューラルネット | 情報集合ごとの表 |
| 手のまとめ方 | **まとめない**（1326 通り全部を同時に計算） | まとめない（カードをそのまま入力） | 32 個のバケツにまとめる |
| スタックの深さ | 何でも（局面ごとに解く） | 1 つのネットで 10〜200BB | 深さごとに別の表 |
| 1 手にかかる時間 | **1〜2 秒** | 0.1 ミリ秒 | 0.1 ミリ秒 |
| 学習 | ネットを土台にする（`train_deep.py`） | `train_deep.py`（GPU + CPU 並列） | `train.py`（CPU） |
| 保存 | `checkpoints/*.pt`（ネット） | `checkpoints/*.pt` | `checkpoints/*.npz` |

### なぜその場で解くのか

ネットだけの版は、ルールベース相手に +70 mbb/hand（ほぼ互角）しか勝てず、100BB で 44 や AK を
オールインするなど、人間に読まれる粗さが残っていた。Deep CFR は全部の局面を 1 つのネットで
**だいたい**覚える方式で、1100 万局たどっても均衡には遠い。

ソルバーは**目の前の 1 局面だけ**を解く。両者の「持ちうる手の分布（レンジ）」を 1326 通りの
ホールカード全部について同時に持ち、この先の賭けの木を CFR+ で 100〜150 回反復すると、
その局面の中では搾取されやすさがポットの 1% 以下まで下がる（`solver.exploitability()` で測れる）。
Libratus / Pluribus が人間に勝ったときの「その場で読み直す」部分に当たる。

表形式には**深いスタックが弱い**という弱点があった。実測で、100BB の表はルールベース相手に
-165 mbb/hand（負け越し）だった一方、10BB の表は +344 mbb/hand で勝っていた。理由は単純で、
深い方は情報集合が 20 万個もあるのに学習が 130 万回しか回らず、1 つあたり 7 回しか経験して
いなかった（浅い方は 130 回）。深さごとに表が分かれているので、経験を共有できない。
ニューラルネットにすると**深さは入力の 1 つ**になり、浅いところで覚えたことが深いところにも効く。

## 先に小さなポーカーで確かめる

本物のホールデムは大きすぎて「本当に均衡に近づいたか」を直接は確かめられない。
そこで**答えが分かっている小さなポーカー**で実装の正しさを先に裏取りしている（`tests/poker/test_cfr.py`）。

- クーンポーカー（カード 3 枚）: 理論上の均衡を入れると **exploitability が 0**、
  先手の期待値がちょうど **-1/18**。測り方そのものが正しいことの確認になる。
- CFR+ を回すと、クーンポーカーは 2000 反復で 4.4e-5、Leduc ホールデムは 400 反復で
  0.0013 まで搾取されやすさが下がる。

> 実装したとき、**1 回の反復の途中で戦略が変わってしまう**バグを入れていた。同じ情報集合の
> 別々の局面が違う戦略で計算され、収束が 1/√T（素の CFR 相当）まで落ちていた。
> 走査の間は戦略を固定し、後悔の増分は最後にまとめて足すよう直したら、Leduc の
> 搾取されやすさが 26 分の 1 になった（しかも 2 倍速くなった）。`cfr.py` の `_Pass` 参照。

## その場で解く（ソルバー）の作り

**レンジ**（`search.py`）: 局の始まりは両者とも 1326 通りが同じ重み。行動が 1 つ進むたびに
「その手札なら、その行動をどれだけの確率で選んだか」を掛けていく。

- 自分の行動は、自分が解いたときの平均戦略（1326 通りぶん出る）で掛ける。
- 相手の行動は、**ネットの推定**と**ソルバーが出した相手の均衡戦略**を半々で混ぜる（`net_weight`）。
  ネットだけだと、ネットの想定が甘い手（100BB のオールインなど）を人間に「強い手だけで」
  打たれたときに広く受けすぎて損をする。均衡を混ぜるとそこが締まる。
  さらに `epsilon`（5%）で「どの手も打ちうる」を混ぜ、想定外の手でレンジが 0 になるのを防ぐ。
- 相手のレンジからは、自分の手札とかぶるコンボを外す。

**木**（`solver.build_tree()`）: いまのストリートの賭けだけを組む（手の枠は学習と同じ
「降りる・チェック/コール・0.5 ポット・1 ポット・オールイン」、1 ストリート 2 レイズまで）。
ストリートが終わるところは次のように扱う。

- リバー: 本当のショーダウン（強さ順に並べて累積和を取る。ブロッカーも正しく引く。`SortedShowdown`）
- ターン・フロップ・プリフロップ: **そのままショーダウンしたときの期待値**で打ち切る（深さ制限）。
  ランアウト（この先めくれるカード）を平均した 1326 × 1326 の行列 `E[i, j] = 平均 sign(強さ_i − 強さ_j)`
  を作り、`E @ 相手のレンジ` で 1326 通りまとめて求める（`EquityLeaf`）。ターンはリバー 48 通り全部、
  フロップは見本 100 通り、プリフロップは見本 1500 通り（1 回作ってファイルに残す）。
  行列は低ランク（160）に縮めて持つ。7MB のままだと 1 反復に何十回も掛けるときメモリの帯域で
  頭打ちになり、**プロセスを 8 つ並べてもまったく速くならなかった**。縮めると 1.7MB で 5 倍軽い。

**反復**: DCFR（後悔の割引、α=1.5, β=0, γ=2）。CFR+ の半分の反復で同じ均衡からの距離になる。
両者を交互に更新し、1 反復は「自分の各手の反実仮想の価値を (K, 1326) の配列で一度に」計算する。
フロップ 120・ターン 120・リバー 150 反復で、1 手 1〜2 秒。

**プリフロップ**は局面がスタックと履歴で決まるので、解いた結果を使い回す（`preflop_solution()`）。

### 分かっている粗さ

- **深さ制限の葉が「そのままショーダウン」**なので、この先の賭けで得られる分（バリューベット・
  ブラフ・ポジションの価値）を見ていない。ターンでリバー 48 通りの賭けまで組む
  `turn_rivers` も入れてあるが、木が 800 ノードになり 1 手 60 秒以上かかるので既定では使っていない。
- 同じ理由でプリフロップは**スーテッドコネクターの伸びしろを見ない**ので、SB が 65s や 38s を
  降りるなど、本物の均衡より固い。降りるときの損は 0.5BB なので致命的ではないが、伸びしろ。
- 相手のレンジは「ネット + 均衡」のモデルなので、人間がそこから大きく外れた打ち方をすると
  推定がずれる。ただし均衡に近い打ち方は、相手が外れても期待値で負けにくい。

## ニューラルネット（相手のモデル・土台）の作り

**入力**（`encoding.py`、146 次元）: 自分のホールカード 52・ボード 52・ストリート 4・
手の強さ・引きかけの種類・役のカテゴリ・プリフロップの形・チップの状況・行動の履歴の要約。
**相手のホールカードは入れない**（入れたらカンニングになる。テストで縛ってある）。

**ネット**（`model.py`）: 3 層 × 256 の全結合。2 つ使う。

- **advantage ネット**: 局面 → 各手の後悔の予想。学習中の打ち方はこの予想から作る。
- **strategy ネット**: 局面 → 各手を選ぶ確率。**遊ぶのはこちら**（CFR で強くなるのは
  「学習中の打ち方の平均」なので、それを覚えさせる係）。

**1 反復の流れ**（`deep_cfr.py` / `train_deep.py`）:

1. 木をたどって学習のもとを集める（12 プロセス並列）。学習する側の手番では打てる手を全部試す。
2. 貯めた後悔を目標に advantage ネットを**まっさらから**学習し直す（Deep CFR の作法。
   古い予想に引きずられると間違いが積み上がるため）。
3. ときどき strategy ネットも作り、強さを測って `best.pt` に残す。

### 速さのために気をつけたこと

木をたどる間は**1 局面ずつネットを呼ぶ**ことになるので、1 回の呼び出しの手間がそのまま効く。

- **BLAS のスレッド数を 1 にする**。小さな行列積では、スレッドを起こす手間の方が高くつく。
  16 スレッドのままだと 3 倍遅かった（`train_deep.py` の先頭で環境変数を設定）。
- **LayerNorm を使わない**。numpy だと 1 層で 7 回も配列演算が要り、ネット 1 回 117 マイクロ秒の
  大半を占めていた。外して 20 マイクロ秒になった。
- **カード由来の特徴量は (プレイヤー, ストリート) ごとに 1 回だけ**計算して使い回す。
  賭けがどう進んでも変わらない部分なので。
- **貯水池への追加をまとめて行う**。1 件ずつだと 1 反復で数秒かかっていた（100 倍速くなった）。
- **後悔は開始スタックで割ってから**ネットに覚えさせる。チップのままだと深いスタックの局だけ
  桁が 20 倍大きくなり、そこばかりに引っぱられる。手の選び方は後悔の「比」で決まるので割ってよい。

以上で 1 プロセス 300 対局/秒、12 プロセスで合計 1300 対局/秒ほど。

## 学習する

```powershell
cd backend
.\.venv\Scripts\python -m rl.poker.train_deep --run-name n1                 # ニューラルネット（本命）
.\.venv\Scripts\python -m rl.poker.train_deep --run-name n1 --resume
.\.venv\Scripts\python -m rl.poker.train_deep --run-name dbg --workers 0    # 1 プロセス（デバッガで追う）
.\.venv\Scripts\python -m rl.poker.train_deep --help
```

`runs/poker/<名前>/` に config.json / metrics.jsonl / evals.jsonl / status.json / checkpoints/ を書く。
`python manage.py sync_runs` で `/poker/stats` に出る。
`--resume` は advantage ネットから続ける（貯めたデータは残していないので、貯め直しになる）。

表形式版（比較用）はこちら。深さごとに別プロセスで回して `merge.py` でまとめる。

```powershell
.\.venv\Scripts\python -m rl.poker.train --run-name v1-100bb --depth 5
```

## 強さの測り方

ポーカーは運の幅が大きく、素朴に対戦させると 1 万局打っても差が見えない。そこで
**同じカードを配って席を入れ替えて 2 回打つ**（ミラー方式）。カードの運が打ち消し合う。

単位は **mbb/hand**（1 局あたりビッグブラインドの 1/1000 が何個か）。+50 でかなり勝っている。

```powershell
cd backend
.\.venv\Scripts\python -m rl.poker.evaluate --agent n1:latest --workers 8 --hands 2400   # その場で解く
.\.venv\Scripts\python -m rl.poker.evaluate --agent n1:latest --opponents n1:latest:net --workers 8   # ネットだけと直接対戦
.\.venv\Scripts\python -m rl.poker.evaluate --agent n1:latest:net --hands 24000            # ネットだけ（速い）
```

AI の ID は API と同じ（`n1:latest` = その場で解く、`n1:latest:net` = ネットだけ、`heuristic` など）。
その場で解く AI は 1 手 1〜2 秒かかるので `--workers` で分ける（8 プロセスで 1 秒に 4 局ほど）。

実測（100BB・2400 局・ミラー方式、2026-09）:

| 対戦 | 結果 |
|---|---|
| その場で解く vs ルールベース（かたい） | **+429 ± 409** mbb/hand |
| その場で解く vs ネットだけ（n1:latest:net） | **+1412 ± 397** mbb/hand |
| （参考）ネットだけ vs ルールベース | +70 mbb/hand（学習中の 1 万 2 千局の評価） |

ネットだけの版を直接対戦で大きく上回る（標準誤差の 3.5 倍）。ルールベース相手の数字は
ブレが大きく（2400 局では ±400）、符号が正であること以上は言えない。

> それでもブレは大きい。同じ戦略が 4000 局の評価で +392、24000 局で -165 になったことがある。
> **評価の局数をケチると「一番よい重み」の選択がほぼ運になる**ので、`--eval-hands` は
> 1 万局以上にしてある。また「一番よい」の判定には**でたらめ相手の成績を使わない**
> （でたらめ相手の成績は青天井に伸びるので、手強い相手への強さが埋もれてしまう）。

「簡単に退場しないか」は別に測る（`evaluate.survival`）。スタックを持ち越して片方が
尽きるまで打ち、自分が尽きた割合を見る。

## 気をつけること

- **`encoding.py` を変えたら `FEATURE_VERSION`、`config.py` を変えたら `ABSTRACTION_VERSION` を上げる**
  （テトリスの `FEATURE_VERSION`、オセロの `PATTERN_VERSION` と同じ）。古い重みは使えなくなる。
  版が違う重みを読もうとすると `model.PokerNet.load` が例外を投げる。
- レイズ額の枠は `games/poker/rules.py` に 1 つだけ置く。学習側と画面側で別々に持つと、
  **学習していない手を AI に打たせる**事故になる（`tests/poker/test_learning.py` で縛ってある）。
- 情報集合に**相手の手札を入れてはいけない**（カンニングになる）。ネット版は
  `tests/poker/test_deep.py` の「相手のホールカードは特徴量に入らない」で縛ってある。
- 後悔マッチングで**全部の後悔が同点のときは均等に混ぜる**こと。「先に見つけた手」を選ぶと、
  学習前（予想が全部 0）に必ず同じ手だけを打つ AI になり、木が潰れて何も学べない。
- ルールベース（`players.heuristic`）は**比較の基準**であって AI 本体ではない。
  表形式版だけは「知らない場面」があるのでそこの穴埋めにも使うが、ネット版には不要。

## この先

- 深さ制限の葉を賢くする。「そのままショーダウン」ではなく、次のストリートの賭けまで組む
  （`turn_rivers`）か、Pluribus のように「いくつかの決まった続け方」から相手に選ばせる。
  木のノードを valid なコンボだけに絞る・Cython 化するなどで速くすれば、ターンでリバーまで
  組めるようになる。
- ネット（相手のモデル）を長く学習する。Deep CFR は反復数がそのまま効く。
- ベット額の枠を増やす（今は 0.5 ポット・1 ポット・オールイン）。ソルバーは局面ごとに木を組むので、
  枠を増やしても学習し直しは要らない（ネットの側だけ `ABSTRACTION_VERSION` が上がる）。
- 3 人以上の卓。均衡の保証は消えるが、Pluribus と同じ考え方で「だいたい強い」ものは作れる。
